# v3.29.0 — Run ID & Correlation ID

## Purpose

Phase 8 gives every CLI execution a unique Run ID so terminal logs and execution results can be correlated across the same run.

## Identity model

- **Run ID:** `run-<12 hex characters>`; generated once at CLI startup.
- **Test ID:** `<runId>-test-1` for the current execution result.
- **Step ID:** `step-<12 hex characters>` for each execution step.
- **Thread-local context:** `RunContext` keeps the active Run ID scoped to the current execution thread and removes it when the run closes.

## Terminal logs

`RunLogManager` accepts the Run ID and includes it in:

1. The terminal log filename.
2. The run-start marker.
3. Every managed log line.
4. The run-finished marker.

The existing redaction and live terminal tee behavior remain unchanged.

## Backward compatibility

`RunLogManager.start(reportsDir, area, command)` remains available. When no active context exists it generates a Run ID automatically.

`ExecutionResult` keeps a no-argument constructor and Jackson-compatible public fields, so existing persisted execution history remains readable. Older results without identity fields can call `ensureIdentity()` to populate current correlation information.

## Verification

`RunContextTest` verifies Run ID format, result correlation, step identity, and cleanup of the thread-local context.
