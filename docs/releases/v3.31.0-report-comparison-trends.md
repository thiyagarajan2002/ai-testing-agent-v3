# v3.31.0 — Report Comparison & Trend Analysis

## Goal

Extend the v3.30 execution-history layer with a derived trend dashboard covering pass rate, duration, regressions and cumulative flaky-test signals.

## Generated artifacts

Under `reports/history/`:

```text
trends.json
trends.csv
trends.html
```

The trend dashboard is derived from `index.json` and each persisted `suite-execution.json`. Existing run records are not modified.

## Metrics

- **Pass-rate delta:** latest analyzed pass rate minus the first analyzed pass rate, expressed in percentage points.
- **Duration delta:** latest duration minus the first analyzed duration.
- **Regression total:** sum of recorded regressions in the selected history window.
- **Peak duration:** maximum suite duration in the selected window.
- **Flaky-test trend:** cumulative count of tests whose historical status alternates between PASS and FAIL with a status-change rate of at least 50%. A single execution is never considered flaky.

## Navigation

Each trend row links to the corresponding run's `comparison.html`. The dashboard also links to `index.html`, `analytics.html`, and machine-readable JSON/CSV outputs.

## CLI

```text
mvn exec:java -Dexec.args="history"
mvn exec:java -Dexec.args="history --limit 20"
```

The history command refreshes only derived analytics/trend artifacts. Persisted execution records remain unchanged.

## Validation

`TrendAnalyticsManagerTest` covers:

- pass-rate delta
- duration delta
- regression aggregation
- peak duration
- trend point count
- JSON/CSV/HTML artifact generation

## Scope

This phase deliberately keeps trend generation deterministic and dependency-free. It does not introduce a charting JavaScript dependency or alter the existing HTML execution report contract. A future reporting phase can embed richer charts directly into `ReportManager` while continuing to consume these stable trend artifacts.
