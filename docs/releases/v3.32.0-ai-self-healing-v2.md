# v3.32.0 — AI Self-Healing v2

## Goal
Strengthen the existing UI locator healing without introducing unsafe broad selector guessing.

## Changes
- Added a configurable confidence threshold to `SelfHealingEngine`, defaulting to `0.90`.
- Candidate evaluation now records match count, visibility, confidence and rationale.
- A candidate is accepted only when it meets the threshold and resolves to exactly one visible element.
- Healing remains deterministic and derives candidates only from the original selector.
- Failed healing attempts are included in UI step details and failure metadata.
- Sensitive evidence continues through `SecurityRedactor` before it is persisted.

## Safety model
1. Classify the original failure.
2. Attempt healing only for locator-class failures.
3. Generate conservative candidates from the original selector.
4. Reject candidates below the confidence threshold.
5. Require exactly one match and visible state.
6. Execute only the accepted candidate.
7. Preserve failure artifacts when healing cannot recover the test.

No generic XPath generation, text guessing, JavaScript injection, or unrestricted DOM mutation is performed.

## Regression coverage
`SelfHealingEngineTest` continues to verify conservative candidate generation. `SelfHealingEngineConfidenceTest` verifies confidence validation and candidate scoring.

## Compatibility
Existing `SelfHealingEngine.heal(page, locator)` remains available and uses the default confidence threshold. The four-argument `HealingResult` constructor remains available for compatibility with existing callers.
