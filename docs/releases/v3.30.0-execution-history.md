# v3.30.0 — Execution History

## Goal

Make suite executions durable and comparable so a test engineer can inspect previous runs, identify regressions, and detect flaky or slow tests without changing the existing report package.

## Storage

```text
reports/history/
├── index.json
├── index.html
├── analytics.json
├── analytics.csv
├── analytics.html
└── <run-id>/
    ├── suite-execution.json
    ├── comparison.json
    ├── comparison.csv
    └── comparison.html
```

## Recording flow

1. A suite is executed.
2. `RunHistoryManager.recordSuite(...)` creates a unique historical run ID.
3. The complete suite result is stored in the run directory.
4. The run is compared with the previous recorded run.
5. JSON, CSV and HTML comparison artifacts are generated.
6. `index.json` and `index.html` are updated.
7. `HistoryAnalyticsManager` calculates recent-run statistics, flaky tests and slowest tests.

## Comparison categories

- `NEW_TEST`
- `REGRESSION`
- `FIXED`
- `PASSED_UNCHANGED`
- `FAILED_UNCHANGED`
- `REMOVED_TEST`

Test identity is based on normalized plan path plus test name, preventing unrelated tests from being compared as the same test.

## CLI

```text
mvn exec:java -Dexec.args="history"
mvn exec:java -Dexec.args="history --limit 20"
```

The command reads `reports/history/index.json`, prints the requested recent runs, and reports the number of observed and flaky tests. It also prints the generated dashboard paths.

## Analytics

Historical analytics uses a bounded run window and reports:

- executions, passes and failures per test
- status changes
- flakiness rate
- average duration
- ten slowest tests

A test is considered flaky only when it has at least two executions, both pass and fail observations, and meets the configured threshold.

## Safety

History is separate from the deterministic three-file execution report package. Existing security redaction remains applied to generated comparison text. Historical data should still be treated as test evidence and should not be committed when it contains environment-specific or sensitive runtime information.

## Regression tests

`RunHistoryManagerTest` verifies:

- suite history is persisted
- the history index is created
- regression detection works
- fixed-test detection works

## Scope

v3.30 focuses on suite execution history. Plan-level history, richer trend visualization, report-to-history deep links, retention policies and database-backed history remain future enhancements.
