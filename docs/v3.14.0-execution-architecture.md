# v3.14.0 — Execution Architecture Refactor

## Purpose

v3.14.0 introduces `TestOrchestrator` as the application execution-coordination layer. The CLI entry point no longer owns configuration, environment loading, plan/suite loading, execution, reporting, and history coordination directly.

## New component

`src/main/java/com/thiyagarajan/agent/runtime/TestOrchestrator.java`

Responsibilities:

- validate plan/suite input files;
- deserialize JSON into `TestPlan` and `TestSuite`;
- construct and coordinate `AgentRunner`;
- load and apply an optional environment profile;
- execute plans and suites;
- invoke failure analysis when a plan fails;
- write plan and suite reports;
- record suite history and analytics;
- expose only the runtime operations required by the CLI.

## Main changes

`Main.java` is now a thin entry point responsible for:

- command dispatch;
- interactive input;
- console output;
- deterministic process exit codes.

`Main` delegates execution lifecycle work to `TestOrchestrator`.

## Execution flow

```text
CLI arguments
     ↓
Main
     ↓
TestOrchestrator
     ├── Config
     ├── EnvironmentManager
     ├── AgentRunner
     │    ├── ApiExecutor
     │    └── UiExecutor
     ├── ReportManager
     └── SuiteReportManager
          ↓
ExecutionResult / SuiteExecutionResult
          ↓
Reports / Failure Analysis / History / Analytics
```

## Public operations

### `executePlan(String file)`

Loads a plan, validates the file, applies the optional environment profile, executes the plan, performs optional failure analysis, and writes the execution report.

### `executeSuite(String file)`

Loads and validates a suite, executes it with the configured parallelism, generates suite reports, and records history/analytics.

### `plan(String requirement)`

Delegates natural-language test-plan generation to `AgentRunner`.

### `execute(TestPlan plan)`

Delegates execution of an already-created plan to `AgentRunner`.

### `analyzeIfFailed(TestPlan, ExecutionResult)`

Attempts AI-assisted failure analysis while keeping analysis failure isolated from the underlying test result.

### `writeReport(ExecutionResult)`

Delegates execution-report generation to `ReportManager`.

## Validation behavior

Missing plan files produce `PLAN_VALIDATION` errors.

Missing suite files produce `SUITE_VALIDATION` errors.

Null orchestrator dependencies produce `CONFIGURATION` errors.

The existing v3.13 standardized error categories and exit-code contract remain unchanged:

```text
0 = success
1 = executed test/plan/suite failed
2 = configuration, validation, application, or infrastructure error
```

## Tests

`TestOrchestratorTest` verifies:

- null configuration rejection;
- null mapper rejection;
- missing plan categorization;
- missing suite categorization.

## Compatibility

The JSON plan model, suite model, API/UI executors, assertion engine, retry behavior, reporting, history, analytics, security redaction, and CI workflow remain compatible with the v3.13 execution model.
